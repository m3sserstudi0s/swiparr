# MESSER.md — Messer Swipe

Port: **1 (React)** · Brand: **`brand-messer-swipe`** (neutral accent, `oklch(.30 .008 260)` light /
`oklch(.92 .004 260)` dark) · Sink: **`/ui`** · Canon: **messer-ui 2.0.0**

Tokens, type and the brand file are generated by `messer-ui` and copied into `src/styles/messer/`
(`node ~/Repos/messer-ui/scripts/install.mjs --app . --brand messer-swipe --dir src/styles/messer`).
Components stay local, so patches are ordinary edits and upstream deltas stay visible through
`shadcn add <item> --diff`.

## Local decisions

- **No primary colour.** The accent is the neutral the Portal and Studio use, so every `bg-primary`,
  `text-primary` and `--chart-*` surface resolves to ink or paper. There is no hue in the chrome; the
  only colour on screen comes from poster artwork. The mark is ink-on-paper and never the accent.
- **Icons are Lucide** (`lucide-react`). Canon §9 fixes Phosphor for the family and allows one
  declared exception per app; this is it, recorded in `messer-ui/scripts/apps.json`
  (`iconFamily: "lucide"`). `messer check --static` enforces the declaration in both directions, so
  a stray Phosphor import fails the build. The mark glyph is Lucide `layers` (`mark.source: "lucide"`)
  — a stroke mark, drawn at Lucide's own 2/24 weight.
- Layout, sidebar mapping (`--sidebar-*` → surface/text tokens), navigation shape.
- Deck interactions (swipe, match overlay) — behaviour, not style.
- Copy voice.

## Names that did not change

The rebrand stops at the product surface. These identifiers are contracts or user state; each one
would break somebody:

| Identifier | Why it stays |
|---|---|
| cookie `messer-swipe-session` | **renamed**, with a migration: `proxy.ts` copies an existing `swiparr-session` cookie onto the new name and clears the old one, so nobody is logged out |
| localStorage `messer-swipe-settings` | **renamed**, with a migration: the first read falls back to `swiparr-settings` and moves it (`src/lib/settings.ts`) |
| `window.__MESSER_SWIPE_CONFIG__` | renamed outright — it is written and read in the same page load |
| database file `swiparr.db` | data path on a mounted volume; a rename is a file move for zero user benefit |
| `SCRYPT_SALT = "swiparr-guest-lending-v2"` | it is the KDF input for every stored guest access token; changing it makes them undecryptable |
| Plex client id key `swiparr_plex_client_id` | holds the device Plex has already registered; a new key forces every Plex user to re-authorise |
| `APP_PUBLIC_URL` default `swipe.messer.wtf` | the hosted demo domain; `swiparr.com` 301s to it via `LEGACY_REDIRECT_FROM` |

## Notes from adoption

- `next lint` no longer exists in Next 16 and `eslint-config-next` was pinned to `^0.2.4` (a stub), so
  lint had never run. Fixed: `eslint-config-next@16.1.6`, `eslint@^9`, `npx eslint src`.
  Pre-existing `any` and React-Compiler-era rule violations are **warnings**, not errors.
- Icons came back to Lucide at 2.0 (`@phosphor-icons/react` removed). The sweep renamed identifiers
  only — no copy string was touched.
- The OG card and the app mark both come from `marks/messer-swipe/` in messer-ui; `public/icon0.svg`,
  `icon1.png`, `favicon.ico` and the `web-app-manifest-*.png` set are gone.
- The sink is public in development and behind the session in production unless `MESSER_SINK_PUBLIC=1`
  (see `src/proxy.ts`).
